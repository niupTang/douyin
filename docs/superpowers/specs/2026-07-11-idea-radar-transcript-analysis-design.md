# 观点雷达视频正文拆解设计

## 目标

观点雷达必须先获取对标视频的完整口播文案，再根据正文完成内容拆解和机会分析。标题只作为补充信息，不能继续把标题分析展示成完整视频分析。

本次保持现有观点雷达页面和路由，不重做页面布局。改动聚焦于后端解析链路、分析提示词、结果缓存和最少量状态展示。

## 当前问题

当前 `generate_idea_radar()` 主要依赖作品标题、点赞量和关键词分类，并使用固定的人群焦虑、反常识观点与推荐标题。不同作品容易得到相似结论，且无法判断原作的完整论证、案例、情绪和机会转折。

项目虽然已有本地 Whisper 转写脚本，但尚未接入对标作品，也没有视频下载、转写状态、正文缓存和失败重试链路。

## 处理流程

1. 用户在观点雷达选择一条对标作品。
2. 后端读取该作品已经缓存的转写和分析。
3. 如果没有有效转写，创建解析任务。
4. 优先使用 `yt-dlp` 和当前抖音登录 Cookie 下载视频。
5. 下载失败时，使用 Playwright 打开作品页并从媒体请求中获取真实视频地址。
6. 使用 FFmpeg 提取适合语音识别的单声道音频。
7. 使用本地 `faster-whisper` 转写中文口播，保留全文和时间戳片段。
8. 清理无意义重复、口头停顿和明显识别噪声，但同时保留原始转写。
9. Codex 根据完整文案完成对标拆解。
10. Codex 再根据拆解结果完成机会分析。
11. 保存结果；再次打开同一作品时直接读取缓存。

## 数据与状态

为每条对标作品保存以下信息：

- 解析状态：`pending`、`processing`、`success`、`failed`。
- 分析依据：`transcript` 或 `title_only`。
- 原始转写全文。
- 清洗后的正文。
- 带开始和结束时间的转写片段。
- 转写引擎、模型、语言和媒体时长。
- 失败原因、创建时间和更新时间。

同一作品只保留一份当前结果。用户主动重试时覆盖旧结果。成功结果默认复用，避免重复下载、重复转写和重复模型调用。

## 对标拆解提示词

对标拆解只能从提供的正文和元数据中提取结论，并区分事实与推断。输出应包括：

- 一句话主题；
- 目标人群和具体处境；
- 开头钩子及其作用；
- 内容结构和每段承担的任务；
- 核心观点；
- 使用的案例、数字、经历和其他证据；
- 情绪变化和认知转折；
- 传播承诺；
- 可借鉴的表达机制；
- 依赖作者身份或个人经历、不可直接复制的部分；
- 信息缺口和分析置信度。

不得只根据关键词判断主题，不得编造正文中没有出现的案例、数字或用户反馈。

## 机会分析提示词

机会分析建立在对标拆解之后，不直接从标题生成。它必须回答：

1. 作品揭示了什么变化信号；
2. 哪种成本、门槛或分工正在下降或改变；
3. 原来谁能做，现在谁也可能做到；
4. 哪类人出现了什么未满足需求；
5. 普通人可以提供什么具体交付物；
6. 谁可能付钱，为什么愿意付钱；
7. 如何用最低成本验证；
8. 机会的时效、风险和不成立条件；
9. 如何迁移成符合用户账号定位的内容。

机会分析不能停留在“值得关注”“普通人可以抓住机会”等空泛表述。没有充分证据时必须标记为假设或待验证判断。

## 接口行为

保留现有作品列表和分析入口。分析接口返回：

- 当前解析状态；
- 分析依据；
- 可读的正文；
- 对标拆解；
- 机会分析；
- 错误信息；
- 是否允许重试。

解析属于耗时任务，接口不长时间阻塞。首次请求创建后台任务并返回 `pending`，前端轮询状态；完成后展示结果。

## 前端最小改动

观点雷达继续使用现有两栏布局，只增加：

- “正在下载视频”“正在转写”“正在分析”的状态；
- 分析依据标签；
- 转写正文折叠区；
- 失败原因和“重新解析”按钮。

现有的人群焦虑、反常识观点、可迁移方向、证据类型、推荐标题和口播开头继续展示，但内容改为基于正文的模型输出。

## 失败处理

- 没有可用抖音 Cookie：提示先在账号管理登录抖音。
- 视频不可下载或已删除：保存失败原因并允许重试。
- Whisper 未安装：返回明确依赖错误，不静默降级。
- 转写为空：标记失败，不把空文案送入分析。
- Codex 调用失败：保留成功转写，允许只重试分析。
- 仅标题分析：必须显示 `title_only`，不得显示成完整拆解。

## 依赖与存储

- 复用当前已安装的 `yt-dlp` 和 FFmpeg。
- 为项目虚拟环境加入 `faster-whisper`。
- Whisper 模型默认使用适合 CPU 的小型中文模型，模型名允许通过环境变量配置。
- 临时视频和音频在任务结束后清理；正文和分析写入 SQLite。

## 验证标准

选择三种不同作品进行验证：开源工具、个人成长和 AI 教程。

每条作品应满足：

- 能看到完整或足够长的正文，而不是作品标题；
- 拆解结果引用正文中的实际观点或案例；
- 三条作品不会得到相同的固定人群焦虑；
- 机会分析包含受影响人群、具体交付物、潜在付费者和最小验证动作；
- 推断与事实明确区分；
- 再次打开时直接命中缓存；
- 下载、转写或分析失败时可看到真实原因并单独重试。

## 范围限制

本次只支持已经进入抖音对标库的作品，不扩展到小红书、视频号或快手。不实现批量转写全部历史作品，不重做雷达页面，不自动生成或发布公众号文章。
