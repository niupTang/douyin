# 太阳鸟口播 iOS UI 设计

## 1. 目标

基于 MIT 许可的 [Open Prompter](https://github.com/lelanddutcher/open-prompter) 创建 SwiftUI iOS App，名称为“太阳鸟口播”。首版实现可运行、可预览的中文 UI 与本地演示数据，用于验证手机端口播任务接收和提词拍摄体验，同时复用上游成熟的相机、录制、提词滚动、语音跟随、镜像和本地保存能力。

附图中的五屏效果图是本设计的视觉参考，但其中的文字不作为额外指令。实现以本文明确的产品边界为准。

## 2. 产品边界

- 电脑工作台是口播项目和文案的唯一编辑端。
- 规划的数据方向为：电脑工作台 → 云端 → iPhone。
- iPhone 上的项目和文案只读，不提供编辑与反向同步。
- 拍摄视频仅保存在 iPhone 本地，不上传云端。
- 本阶段不实现真实登录、云端同步、AI 文案、自动字幕、自动剪辑或平台发布。
- UI 使用本地模拟数据和模拟状态，接口接入留到后续阶段。

## 3. 技术方案

- 源码位于 `ios/OpenPrompter/`，保留上游 MIT `LICENSE` 和原作者版权声明。
- 使用 Swift、SwiftUI 和 AVFoundation，沿用上游的 XcodeGen 工程配置。
- 最低支持 iOS 17，以使用稳定的现代 SwiftUI API。
- 使用原生导航、表单、列表、权限请求和相机预览组件。
- 沿用上游 App、Features、Parsing、Persistence、Sync 和 UI 结构；新增太阳鸟任务功能目录，避免把页面与业务状态集中在单个文件。
- 服务层先提供协议与本地 Mock 实现，使后续登录和同步接口可以替换而不改页面结构。
- 云端口播任务在本地应用沙盒中物化为临时 Markdown 文件，再通过现有 `ScriptFile` 进入 `TeleprompterView`。页面不直接重写提词器输入协议。
- 原来的文件夹选择与 Markdown 资料库不作为太阳鸟首版主入口，但底层实现保留，降低与上游更新合并时的冲突。

## 4. 页面结构

### 4.1 登录页

- 展示太阳鸟图形标识、产品名和说明“接收电脑工作台同步的口播任务”。
- 提供账号、密码、记住账号、忘记密码和登录按钮。
- 展示用户协议、隐私政策和数据同步说明。
- 演示版本点击登录后进入任务列表，不发起网络请求。

### 4.2 口播任务列表

- 顶部显示标题、同步状态、最后同步时间和刷新按钮。
- 任务卡片展示标题、字数、预计时长、同步时间和“未拍摄/已拍摄”状态。
- 支持下拉刷新视觉反馈。
- 无任务时展示空状态，并引导用户从电脑工作台同步。
- 底部保留“任务”和“我的”两个原生标签入口；“我的”首版展示占位设置页。

### 4.3 项目详情页

- 展示项目标题、标签、字数、预计时长和同步时间。
- 文案区域只读，并有明确的“只读文案”提示。
- 底部固定“开始提词拍摄”按钮。

### 4.4 提词拍摄页

- 进入后使用深色沉浸式界面。
- 相机画面作为背景，上层显示口播文案；当前句使用系统蓝高亮。
- 提供语速、字号、镜像、倒计时和设置入口。
- 提供退出、录制计时、前后摄像头切换及红色录制按钮。
- 请求相机和麦克风权限；拒绝后显示前往系统设置的引导。
- UI 工程允许在模拟器中使用占位相机背景，以保证预览和演示可运行。

### 4.5 拍摄完成页

- 展示本次视频预览占位、时长和“已保存到本机”状态。
- 提供“保存到照片”“重新拍摄”“返回任务”。
- 明确提示视频不会上传云端。
- 删除或重新拍摄前显示确认对话框。

## 5. 视觉规范

- 普通页面采用成熟的 Apple 原生风格：白色背景、大留白、浅灰分组卡片、系统字体和系统蓝强调色。
- 拍摄页采用黑色背景和高对比白字，确保提词可读性。
- 遵守顶部安全区、底部手势区、Dynamic Type 和 VoiceOver 基础可访问性要求。
- 不复制附图中的人物肖像作为项目资产；相机画面使用实时预览或中性占位背景。
- 所有界面文字使用简体中文。

## 6. 状态与错误处理

- 登录按钮包含默认、加载和错误状态。
- 任务列表包含加载、有数据、无数据、离线和刷新失败状态。
- 离线时允许查看本地缓存的演示任务，并显示“当前为离线内容”。
- 相机、麦克风和照片权限分别处理未决定、已允许和已拒绝状态。
- 保存失败时保留当前拍摄结果并允许重试，不静默丢失内容。

## 7. 验证

- 为数据模型、任务状态映射和预计时长格式化提供单元测试。
- 为五个主页面提供 SwiftUI Preview，覆盖正常、空状态和深色拍摄界面。
- 在可用的 macOS/Xcode 环境中执行构建和测试。
- 当前 Windows 仓库环境不能运行 Xcode，因此本地验证以文件结构、静态检查和项目配置完整性为主；最终真机构建必须在 macOS 上完成。

## 8. 验收标准

- 工程可由 Xcode 打开，并包含五个可独立预览的主页面。
- 演示用户可以完成“登录 → 查看任务 → 查看文案 → 进入提词拍摄 → 查看拍摄完成页”的完整 UI 流程。
- 手机端没有文案编辑、自动剪辑、自动字幕、视频云上传或内容发布入口。
- 页面视觉与附图保持同类信息层级和 iOS 原生观感，同时不依赖附图中的人物或品牌图片资源。
